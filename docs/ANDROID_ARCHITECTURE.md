# 安卓架构与性能边界

## 现在运行的是什么

界面复用 Vue 3、TypeScript、Pinia 和上游资源，由 Capacitor 的 Android WebView 宿主运行。播放、缓存、网易云会话、本地目录、通知和悬浮歌词由 Android 原生层负责。没有把 Electron 桌面主进程或完整 Chromium 打进 APK。

Vutron 的桌面模板和安卓宿主承担不同的平台职责；换成桌面模板本身不会让手机界面自动更快。当前没有真机内存或能耗数据支持整套改写，也没有必要为了界面字号、排序和定时器引入另一种语言。

## 存储与运行内存

- APK 的主要原生库是多音源回退使用的 libnode.so；解压安装后的大小会高于压缩安装包。删除它会让相关音源回退失效。
- 音频缓存和封面缓存有独立容量限制，设置页分别显示与管理。导入歌单包含应用保存的音频副本；取消读取文件夹不会删除手机原文件。
- 当前没有 WebView 进程的真机测量，不能把 Android 显示的内存用量全归因于应用自己的 JavaScript，也不能宣称节省了某个百分比。
- 设置组件与应用内歌词按需加载；封面模式不挂载歌词列表，也不运行该视图的逐字动画循环。定时读数在前台本地投影，不增加原生桥轮询频率。
- 长曲目列表沿用每批 80 项的渐进加载。没有在本轮重写滑动模型、替换播放引擎或移除多音源运行库。

## 插件化移植到哪里

桌面原版有 PluginManager、每插件 Worker、插件元数据与能力声明、持久化及宿主调用协议。安卓已移植网易云常用功能和部分共享核心，原生平台能力通过 VutronMusicPlugin 桥接。

Capacitor 中名为 Plugin 的桥接类不等于桌面动态音乐插件系统。目前没有移植桌面插件的安装、发现、独立 Worker 宿主、全部能力协议及任意插件兼容层；多音源回退用的内置 Node 运行时也不是完整桌面插件宿主。不能声称安卓已能直接安装所有桌面插件。

继续扩展时，优先在已有平台桥和共享核心边界增加明确能力，保留本地模式联网门禁与回归测试；是否加入动态插件宿主，应作为独立功能设计。

## 应用内控件

页面状态、共享控件行为和视觉检查遵循 [前端界面与交互规范](FRONTEND_UI_CONTRACT.md)。该规范列明现有覆盖与待补的自动视觉基线，避免把构建或单元检查通过当作所有界面状态已经验收。

排序、语言、布局和歌单可见性等选项共用 `AppSelect`，配色、圆角、阴影和动效跟随应用主题。播放顺序直接用按钮循环切换，并显示当前模式。新增应用内选项沿用这些控件，避免 HTML 原生 `select` 唤起样式不同的 Android 选择框；文件选择、权限和安装授权继续使用系统流程。

`AppSelect` 支持键盘、焦点恢复、背景隔离及嵌套弹层，Android 返回先关闭选项。组件浏览器检查覆盖取消、数值类型、语言保存、排序和拖动；`appSelect.test.cjs` 检查 Vue 页面没有重新引入原生选择框。

选项弹层打开时锁定背景滚动，关闭及卸载时恢复原滚动位置和原内联样式。法律正文、歌词页的控制文字和空状态跟随界面字号；歌词正文继续使用独立字号。常见网络、超时、会话、目录授权和空间不足错误提供三语解释及恢复入口，原始诊断保留在可展开详情中。页面重新加载入口仅执行读取，不重复提交歌单创建、删除或喜欢操作。

定时滚轮以总秒数为连续坐标，秒数刻度按 60 循环显示，跨过 59／00 时自动进位或借位；分钟、秒数和读数使用同一份总时长。拖动覆盖标签与刻度所在的整个调整区，输入框保留精确输入。手指移动按小数位置即时反馈，松手吸附与倒计时过渡读取统一动效设置。

歌单自定义拖动使用独立预览与临时顺序，`TransitionGroup` 使其余条目让位；松手才保存，取消恢复原顺序。指针由稳定的列表容器捕获，避免条目移动时丢失拖动。歌曲菜单、队列、评论和倍速面板共用 `useSheetDrag`，支持向下拖动关闭及短距离回弹；已经滚动的内容优先滚动，滑条和输入框保留自身手势。

当前播放页的向下箭头用于收起并返回原页面，不暂停播放。音频在播放器开始流式播放后才排入独立缓存任务；应用内不再提供手动缓存歌曲或批量保存歌单资料的按钮，容量、自动缓存开关及删除管理仍保留。封面下载将两条工作线程保留给可见图片，一条处理后台预缓存；已排队的同一图片可提升到可见通道，下载仍去重，避免首页预缓存堵住详情与搜索封面。

宽度至少 840 CSS px 的横屏窗口同时显示左侧封面和播放控制、右侧歌词；窄窗口保留封面／歌词切换，旋转不改写手机视图偏好。歌词首次点击只标记待跳转句，1.8 秒内再次点击同句或使用确认按钮才定位；拖动、切歌和返回当前句取消待确认状态。楼层回复展开、收起与继续分页分开，收起保留已读回复，重新展开不重复请求。

歌单继续播放由原生 `PlaylistProgress` 按来源与账号保存歌曲身份、CUE 分轨号和进度，沿用播放服务的后台进度检查点及暂停／定位保存，不依赖前端轮询。每台设备最多保留 512 个歌单记录；歌曲已移除时不显示失效的继续入口。继续当前歌单保留现有队列和插队项，切回其他歌单时按其记录与当前曲目顺序创建队列。该设备播放记录不包含 Cookie、音频路径或封面，不作为跨设备目录授权或音频恢复资料。

## 大库测量范围

`VUTRON_TEST_SCENARIO=polish` 的浏览器检查使用 5000 首合成曲目资料，记录分别呈现 80、800、2000 行时的节点数与 JavaScript 堆快照，并检查封面按可见范围加载。当前渐进加载仍会累积节点；这项测量用于后续比较列表实现，不代表 Android 真机 RAM、滚动帧率、扫描耗时或后台耗电结论。
